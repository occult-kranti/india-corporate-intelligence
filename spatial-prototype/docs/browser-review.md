# CI browser review

The browser review is intentionally restricted to GitHub Actions. Do not run or install Chromium locally for this task. Local static syntax checks and the existing model tests are separate from browser verification.

## Repository placement

Publish this standalone package at `spatial-prototype/` and copy `workflow/spatial-review.yml` to repository-root `.github/workflows/spatial-review.yml`. Pull-request path filters include those paths plus the original layout, combined spatial release scripts, deployment workflow and combined release-review workflow. An explicit manual run is also supported. This artifact-only workflow does not modify routes, styles or deployment configuration. There is no deploy step and the token has only `contents: read` permission.

The job uses Node 20, the committed lockfile, the package's unit tests and production build, then [Playwright's CI browser installation](https://playwright.dev/docs/ci). It has a bounded 15-minute job limit to retain the original checks and the historical-reader/atlas-tutorial additions. A failed command remains a failure even when its output is captured in a log.

## What runs

`scripts/browser-review.mjs` launches CI Chromium with ANGLE SwiftShader and a loopback-only, read-only static server. The built app is served only at:

`/india-corporate-intelligence/spatial/`

There is no root asset alias or SPA fallback to mask broken relative asset URLs. Path traversal and symlink escapes are rejected. Each scenario gets a fresh browser context, including empty browser storage. Spatial assertions require actual WebGL draw calls, the MapLibre/Three Mercator renderer marker, and host/canvas rectangles filling at least 90% of the viewport. A nonzero drawing buffer in a collapsed or off-screen host is insufficient. An unexpected reading-mode fallback fails the main spatial checks. Software rendering is only a reproducible CI review environment, not a representative GPU benchmark.

## Isolated review boundary and exact revision

`VITE_HISTORICAL_REVIEW=true` is scoped only to this artifact-only workflow's build step. Normal/default builds do not opt in, and no deployment workflow is changed. The production loading-budget script still runs unchanged. The isolated workflow sets `SPATIAL_EXPECT_HISTORICAL_REVIEW=true` as a test expectation and uses one flagged production build. That expectation requires identifiable deferred gate, payload and reader chunks plus successful positive reader cases; a broken flagged build cannot silently skip them. The default/deployment harness expectation is false when this variable is absent, and it must prove the exact review query stays unavailable with no deferred historical requests. Only positive historical cases 17–20 are then explicitly not applicable. Invalid expectation values fail closed. Neither a query alone nor a disallowed route may request the payload. Diagnostics record the expected mode and actual checks; no build marker, automatic detection or deployment flag change is used.

The independent review anchors are the full original registry hash `048f89ffd008a498212ff2ac71d4413aef09b138a50ab77f336a23fec4722064`, additions hash `5cd5c36de9dd98609c948cf526595a175f30fd29457fa1c7db9cf29b978eaf45` and provenance hash `7ad1b6269af516d7f88dbee5687a6f3ba2cd0ac2f3b97318931d248c382eebf0`. Full expectations reconstruct the original chunks; the exact base remains 2,469 entities, 5,617 records, 4,203 relationships and 3,314 sources. The separate reader adds only the pinned 9 entities, 9 records, 9 relationships and 3 sources. IRB is the original object, present once. Full factual node/edge objects are compared before and after the guarded reader adaptation, not just counted. No synthetic entity or relationship can satisfy these checks. `PUBLIC_GRAPH_BLOCKED` and `publicGraphEligible: false` remain mandatory even after success.

The workflow preserves its normal checkout semantics, including pull-request integration merges. Diagnostics verify checked-out `HEAD` equals `GITHUB_SHA` and that `SPATIAL_HEAD_SHA` (or `GITHUB_SHA` when absent) is either that exact commit or an exact parent of the checked-out integration merge. Raw commit headers work with the existing shallow checkout; no extra fetch or checkout-depth change is needed. The summary separately labels the checked-out commit, candidate head and exact-head/integration-merge coverage. Successful prior-head results cannot substitute for this next-head review.

The atlas guide catalogue is checked against its approved hash `c9cef1fb5f5cded79795573808a5c958e2cdfa092b3567700d89781a3706dfd4`. These bounded atlas cases do not claim completion of original-route tutorials or the wider acceptance matrix. They do not claim that merely rendering static tutorial text proves native-dialog behavior. Live voice playback, every browser's BFCache implementation and original-site return journeys remain outside this bounded review.

The live-building checks require successful provider responses and positive MapLibre `queryRenderedFeatures` counts for the building layer. Missing network data fails that review and remains visible in diagnostics; the separate network-failure scenario cannot substitute for live buildings. Render diagnostics expose center, zoom, pitch, source-qualified placement counts, country-base feature count and building feature count. None of these counts proves pixel quality. The downloaded bounded city sample is checked as a retained derivative, not treated as the worldwide rendered dataset.

Preview expectations come from `src/registry.json` through the existing model. Full expectations reconstruct the built manifest's declared chunks, checking their SHA-256 hashes and the complete snapshot hash before comparison. The reader and factual map are filtered independently, so held context cannot make a factual-map query match indirectly. Semantic expectations use the pure `planSemanticDisplay` planner at the reported camera zoom, checking exact group counts, selected endpoint details and the complete ordered list of rendered original edge IDs. Country stacks remain presentation groups; their totals do not count selected endpoint overlays as additional evidence. The source trail uses the same first source-qualified cross-area relationship as the UI. Visible source cards are checked for exact title, URL, publisher, locator and distinct-source count; raw IDs are checked in the casebook exports and full source catalogue. The unit suite separately checks retained objects against the original registry fixture. Neither stage invents evidence or treats a link as proof of guilt or causation.

## Review artifacts

The workflow preserves these artifacts with `if: always()` for 14 days:

- `spatial-browser-review-<run>-<attempt>`: screenshots, per-scenario JSON, aggregate `diagnostics.json`, DOM snapshots, Playwright trace ZIPs, exported casebook and command logs.
- `spatial-static-preview-<run>-<attempt>`: the production `dist/` directory for inspection; uploading it does not publish a site.

Every attempted scenario captures its final state, including failures, as long as Chromium remains responsive. Setup failures are recorded in aggregate diagnostics. A runner cancellation, browser crash, or job timeout may prevent some captures; inspect preserved logs instead of assuming that a missing image passed. External font failures are recorded but do not establish a local app-asset failure. Vector-tile responses and failures are recorded separately; world/city controls load public provider map data, while the network-failure case deliberately intercepts those requests. No external evidence link is opened or sent data by the review.

Every screenshot also records historical dialog/content and host/canvas bounding rectangles, computed position and dimensions, map diagnostic attributes and loaded stylesheet order in `layoutSamples`; final rectangles are retained in `viewportGeometry`. Semantic assertions additionally retain their mode, counts, selected original ID and exact rendered-edge IDs in `semanticSamples`. The full-default scenario records the pre-import state with no host, then the rendered state after the deferred map module and CSS arrive. This guards the observed lazy-CSS regression where MapLibre's later `.maplibregl-map` rule overrode host positioning and produced a blank viewport despite nonzero WebGL draws. Failing geometry diagnostics remain useful even when image capture fails.

Historical artifacts additionally include per-claim reader captures, exact source/date assertions, review verification/cancellation observations and original base/edge samples. Atlas artifacts include central-note screenshots, target cardinalities, progress/focus results and per-action research-state checks. Every report is labeled next-head review with publication still blocked.

The workflow summary lists pass/fail status, with screenshots and traces in its artifacts. Review the captured image pixels before judging layout, clipping, visual quality or fidelity. No screenshot baseline comparison, pixel-quality approval, hardware FPS measurement, source-truth revalidation, or live deployment is claimed by this check.

## Safe checks without a browser

From the package directory:

- `node --check scripts/browser-review.mjs`
- `npm test`
- `npm run build`

Actual browser-review status remains unverified until the GitHub Actions run for the published revision finishes. The script rejects ordinary local invocation before starting a server or browser.

## Retained first-candidate failure evidence

[Run 38843217469](https://github.com/occult-kranti/india-corporate-intelligence/actions/runs/38843217469) at `4eb3c406` passed 20 of 22 cases. Case 17 used a mistaken no-selection expectation: the retained App initializes the first original node, as case 12 already specifies. Its corrected fixture uses that same exact original selection and still compares every display count and edge ID. Case 22 exposed the legacy mobile CSS hiding Help below 480 pixels. The bounded repair keeps an explicit visible launcher; the regression requires a viewport-contained, uncovered target of at least 44 CSS pixels and actual touch-emulated taps to open and reopen it. Long historical sections are captured in overlapping viewport bands so every expanded qualification and source detail can be inspected, rather than only the first screenful. Neither failure is waived. The failed logs, DOM captures and screenshots remain in the run artifact; a new exact-head run is required.

The passing `16fa4a1` capture exposed a visual contrast defect that automated behavior alone missed: the inherited dark-theme hover rule made a tapped Next button pale on paper. The subsequent guide-only rule keeps dark text, and case 22 requires at least 4.5:1 computed text contrast for all enabled guide buttons after the touch/reopen sequence.
