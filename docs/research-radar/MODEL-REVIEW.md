# Executed discovery and model review

The pinned local model was executed after all four research catalogs were frozen: **87 summaries (64 sources and 23 cases), 64 distinct cited URLs, ten queries, 1.94 seconds of CPU inference**. No result below is a trained corruption predictor. All 50 returned slots were individually reviewed; zero graph edges were automatically promoted.

## Model boundary

The discovery model is `sentence-transformers/all-MiniLM-L6-v2`, pinned to revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`, Apache-2.0. It runs cached, hash-verified ONNX uint8 assets locally on CPU. The 384-dimensional embeddings rank authored public source and case summaries against ten investigative queries. No private record or public text is uploaded to a model service.

The model truncates at 256 tokens. Authored summaries are incomplete representations of originals, and case summaries can repeat their source summaries. Similarity is neither independent corroboration nor identity resolution, a cash-flow edge, factual confidence, guilt, or a future-event probability. Cross-sector retrieval may identify useful documents while suggesting false associations; every proposed association must be rejected unless an exact source supports it.

## Reproduction

From the repository root:

```sh
node scripts/research-radar/model-corpus.mjs
/tmp/india-education-model-env/bin/python scripts/research-radar/model-rank.py --offline
python3 scripts/research-radar/model-rank.py --verify
python3 scripts/research-radar/model-rank.test.py
python3 scripts/research-radar/model-receipt.py
python3 scripts/research-radar/model-receipt.py --verify
```

Verification deliberately fails if any of the four research catalogs or their projected summaries changes. Runtime dependencies are already installed in the isolated existing environment; the stdlib verification path does not execute inference or download assets. CI must use `model-corpus.mjs --verify` to reject stale artifacts rather than silently regenerate them.

- Project or institutional outcome forecasts after outcome definitions, prospectively timestamped features, censoring and reporting-delay handling, temporal/entity holdouts, comparison baselines and calibration validation exist. No such trained predictor is currently released.

No additional agents, model training or background monitoring continue merely because they are listed in the roadmap. An executed run requires a retained receipt; a future system requires implementation and validation.

## Subsequent local fine-tuning experiment · 7 October 2026

The 87-summary discovery execution and 50-result review above remain historical artifacts. A subsequent user-authorized training run used a **separate 64-source-only dataset**, excluding case summaries and their repeated questions. Seventy training questions over 39 source summaries optimized a rank-8 query/value LoRA adapter on the same pinned MiniLM revision. Ten development documents and 16 questions selected the earliest tied checkpoint, epoch 1. Fifteen source documents and 20 independently authored questions across five cases were held out until final evaluation.

This was actual optimization: **73,728 trainable parameters, 72 steps, eight epochs and 143.37 seconds on CPU**, with changed adapter tensors and unchanged frozen base-weight hashes. Training happened on 7 October America/New_York; machine receipts use 8 October UTC. Source limitations and counterevidence remain part of the dataset. No supervised target labels guilt, factual truth or an unresolved institutional forecast outcome.

The candidate's held-out case-macro nDCG@5 was **0.934182**, compared with **0.925522** untuned FP32, **0.897829** existing ONNX uint8 and **0.931317** BM25. The gain over the stronger neural baseline was only **+0.008660**, below the frozen +0.02 threshold, and only one of five cases improved. **The adapter is retained as experimental and was not promoted; `base_onnx_uint8` remains the default retriever.** There was no test-driven second training run. An apparent gain over uint8 alone also includes precision/runtime effects and cannot be attributed entirely to fine-tuning.

See the [model card](fine-tuning/MODEL-CARD.md), [independent evaluation](fine-tuning/EVALUATION.md), [frozen protocol](fine-tuning/EVALUATION-PROTOCOL.md) and [artifact README](../../research/research-radar/fine-tuning/README.md). They record the source-family/material-party split, actual file hashes, custom loader, reproducible commands, all rankings and failed promotion criteria. The test is now public and cannot serve as a newly blind benchmark for further tuning. No source suggestion was automatically promoted into an investigative graph edge, and scenario probabilities remain null.
