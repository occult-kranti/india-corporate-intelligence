# Hypothesis desk: panel record

Review date: 14 October 2026. Participants are AI work roles operating in the shared repository, not a panel of human witnesses or separately commissioned experts. Consensus does not add independent evidence.

## Round 1 — design the investigation before the narrative

The lead established the [research contract](CONTRACT.md), the new-page scope and separate political-finance, resources-contracts and oversight-services acquisition streams. The methods/adversarial reviewer inspected that contract, the prior research memory and methods, the existing data adapter, selected open methods passages and official analytic standards. Design and implementation are separate work roles.

| Decision | Adversarial challenge | Required disposition |
| --- | --- | --- |
| Permit adverse coordination hypotheses. | A plausible story can be generated for almost any network; “alleged” does not make an unsupported accusation evidence. | State a bounded unproved proposition; preserve at least a misconduct mechanism, lawful explanation and data-error alternative, each with distinguishing records. |
| Use strategic decision reconstruction. | The outcome does not reveal preferences, private information or a unique strategy. | Record formal powers, rules then in force, information then available, feasible options and observable implications. Do not invent payoffs, motives or probabilities. |
| Draw network overlays. | A visual line can imply a completed connection despite caveats in prose. | Observed relationships and proposed questions remain different data objects. Question links are optional, have no amounts, and retain missing/disconfirming evidence in popups and exports. |
| Investigate the Modi administrations across sectors. | State authority, corporate conduct and pre-2014 decisions can be wrongly attributed to a Union officeholder. | Date the action; identify the actual decision authority and source. Include earlier context explicitly and avoid personal attribution based only on hierarchy. |
| Find unusual clusters. | A corpus selected for controversy has no representative denominator; degree counts reward publicity and document availability. | Require a defined comparable population and common-cause/selection analysis before describing a cluster as statistically unusual. No crime-risk score from centrality. |
| Add a next-review date. | A scheduled research task can be mistaken for a forecast. | Retrospective tests and prospective acquisition stay explicit. No calibration or “prediction proved” claim without a frozen target and untouched outcomes. |
| Use an independent challenge role. | Multiple agents can repeat the same source or model mistake. | Check original passages and rival explanations. Log specific corrections and unresolved gaps; do not count agent agreement as evidence. |

The reviewer attempted three Exa methods searches; every call returned HTTP 402 credit exhaustion. This was reported to the lead. The reviewer instead inspected known author/official documents directly and reused a clearly labelled retained chapter extract. [METHODS.md](METHODS.md) records scope, source URLs, byte hashes and transfer limitations.

## Final interface and engineering review

The design role performed one batched visual inspection of the built desktop map, network, question reader, 390px and 320px map/question readers, and the 390px source dialog. The petrol/jade hierarchy, warm-paper readers, question status and close controls were accepted without a further code edit. The lead also inspected desktop network and narrow-screen reader captures. Remaining polish opportunities are the mobile introductory controls placing the map below the first viewport and tightly wrapped compact popup tabs; neither blocked the tested workflow.

The validation role completed 37 unit tests and 234 browser checks, including all eight actual case downloads. Question edges remain off by default, dashed when enabled, source-closed in exports, and unable to complete recorded trails. The browser caught a genuine response-attribution issue in the shared reader: the first response in a whole-case closure could belong to another edge. The lead fixed the preview to use the selected edge's own response IDs, and the validator retained exact-response assertions for every recorded and proposed link. There were no browser, console, failed-request or HTTP errors in the accepted new-page run. See [VALIDATION.md](VALIDATION.md) for scope, receipts and inherited exceptions; this interface review does not authenticate the research propositions.
