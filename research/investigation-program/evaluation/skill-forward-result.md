## Forward-test instruction and schema friction

1. **Self-check has no claim-review enum value.** The prose instructs a self-check when independent review is unavailable, but the claim enum offers only `unreviewed`, `independently-checked`, `disputed`, `revised`, `withdrawn`. The example retains a listed value plus `reviewMode` and a note. An explicit self-check state or separate review-mode field would avoid this workaround.
2. **Supplied record descriptions need an access distinction.** `full-text` is truthful only for each synthetic packet item, not its described original. The example titles the sources as packet descriptions, logs packet-only access and leaves underlying-original hashes/URLs null. A `supplied-summary` access depth or separate artifact/source objects would make this cleaner.
3. **Source families can vary by claim.** R4 derives the award from R1, the payment from an unseen statement, and the procurement question from its own article; R5 reproduces all three. A single source-level `sourceFamily` is insufficient. The example supplements it with claim-specific family mappings. No family count is treated as a reliability score.
4. **Statement/report date is not a payment period.** The amount schema has a `period` but no dedicated statement date or payment event date. The example leaves the payment period null, retains `2024-06` as a partial statement date extension, and never fabricates June 1 or a transaction date. The dated-assertion `assertedAt` can hold a snapshot/archive date only with an explicit date-kind note.
5. **Attributed non-accusatory statements fit awkwardly.** A reported ordinary payment and a subject's denial are not naturally “allegations.” The example uses `attributed-allegation` for the payment report and `documentary-fact` for the existence/content of the response, with explicit scope. A separate `attributed-report` or source-status qualifier would be clearer.
6. **Path hops are described but not given stable field names.** The example supplies `fromId`, `toId`, `predicate`, `traversal`, `literalSourceSupport`, `status`, `scope`, `requiredDateOverlap`, `contraryRecord`, and `nextCheck`. Required field definitions would improve interoperability, including representation of an unresolved identity hop or a rejected alternative path.
7. **Relation assertions and relation confidence need separation.** `documented` in this synthetic test means a supplied description explicitly states the relationship; it does not mean the original is authenticated or its content independently true. A source-access/authentication flag prevents graphs from presenting packet statements as validated real-world evidence.

The skills were usable without changing them. They correctly directed conservative identity decisions, chronological checks, source-dependence handling, distinct financial stages and a bounded conclusion. This one packet is a workflow test, not a reliability benchmark or a measured accuracy claim. Companion: `/tmp/skill-forward-result.json`.
